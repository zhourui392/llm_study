# LLM 核心名词与底层原理参考手册

本文整理了从零理解现代大语言模型（LLM，如 GPT / Llama 3 / Qwen / DeepSeek）所需的全部核心概念、通俗解释、数学直觉与真实参数构成，可作为随时查阅的基础手册。

## 一、核心名词速查表（Glossary）

| 英文术语 / 缩写 | 中文名称 | 一句话大白话解释 |
|---|---|---|
| **Token / Tokenizer** | 词元 / 分词器 | 把人类文字切成最小基本单元（词、字、词根或字节）并编成整数编号的“查字典工具”。 |
| **Byte-level BPE** | 字节级字节对编码 | 现代主流分词算法：以 256 个 UTF-8 字节为底座，按高频合并常见字词，永不出现未知词 `<UNK>`。 |
| **Embedding** | 词向量（嵌入表） | 一张巨大的查找表：把整数编号（如 `1024`）查表映射成一串固定长度的小数向量（如 4096 维）。 |
| **Weight Tying** | 权重共享 | 小模型常用技巧：让入口查表 `Embedding` 与出口打分 `LM Head` 共用同一份大矩阵，省参数防过拟合。 |
| **Q / K / V** | Query / Key / Value | 每个词通过投影生成的 3 个角色：**Q**（我在找什么）、**K**（我有什么标签）、**V**（我携带的内容）。 |
| **`W_q / W_k / W_v / W_o`** | 投影矩阵 | 把词向量变成 Q/K/V 的 3 个可学习矩阵；`W_o` 负责把多头注意力的结果拼回并汇总融合。 |
| **Scaled Dot-Product Attention** | 缩放点积注意力 | `softmax((Q @ K.T) / √d) @ V`：用点积算词间相关度，除以 `√d` 稳住数值，再加权融合 `V`。 |
| **Softmax** | 归一化指数函数 | 把一组任意大小的打分压成“全部 > 0 且总和等于 100%”的概率或注意力权重分布。 |
| **Causal Mask** | 因果遮罩 | 接龙模型的核心规则：把当前词之后（未来）位置的注意力分数设为 `-∞`，Softmax 后权重严格为 `0`。 |
| **Multi-Head Attention (MHA)** | 多头注意力 | 先用 `W_q/W_k/W_v` 投影，再把向量维度拆成多组小通道并行算注意力，换取多套互不干扰的观察视角。 |
| **Positional Encoding** | 位置编码 | 给每个词贴上“第几个出现”的顺序号牌，防止模型把“狗咬人”和“人咬狗”当成同一个集合。 |
| **RMSNorm / Pre-Norm** | 均方根归一化 / 前置归一化 | “数值稳压器”：进入 Attention/FFN 之前先用向量均方根缩放回稳态（均方根 ≈ 1），防梯度爆炸或消失。 |
| **Residual Connection** | 残差连接 | 贯穿主干的信息高速路：`新 = 旧 + 变化量`，保证叠几十层后原始词义不丢、反向梯度直通底层。 |
| **FFN / MLP** | 前馈神经网络 | 紧跟 Attention 后的“独立思考层”：词与词不交流，各自升维展开特征、非线性激活筛选再压回原维。 |
| **LM Head / Logits** | 语言模型输出头 / 未归一化打分 | 最后一道线性层，把最终词向量映射回整个词表长度的原始得分（Logits），再经 Softmax 变成预测概率。 |
| **Loss / Cross-Entropy** | 损失函数 / 交叉熵损失 | 衡量模型猜下一个词猜得有多离谱的指标：给正确答案分配的概率越高，Loss 越接近 `0`。 |
| **Backpropagation / Chain Rule** | 反向传播 / 链式法则 | 从最终 Loss 出发，用微积分链式法则倒着一层层把“误差责任”分摊给前面每一个参数的算法。 |
| **Gradient / Gradient Descent** | 梯度 / 梯度下降 | 梯度即导数（指示调大参数会让 Loss 变大还是变小）；梯度下降按“减去学习率 × 梯度”的方向迭代改参数。 |
| **Learning Rate / AdamW** | 学习率 / AdamW 优化器 | 学习率控制每次更新迈多大步；AdamW 在纯梯度下降上加了动量惯性、自适应步长和权重衰减。 |
| **Training vs Inference** | 训练 vs 推理 | **训练**要算 Loss 并用反向传播改权重；**推理**把权重只读锁死、去掉反向传播，只跑前向计算。 |
| **Prefill / Decode / Autoregressive** | 预填充 / 解码 / 自回归生成 | 推理两阶段：**Prefill** 一次并行读完用户提示词；**Decode** 每次吐出 1 个词并拼回末尾继续自回归接龙。 |
| **KV Cache** | 键值缓存 | 推理加速核心：把已处理历史词的 `K` 和 `V` 留在显存里，生成新词时只用新词自己的 `q` 查阅，无需重算前文。 |
| **Sampling (Greedy / Temp / Top-k / Top-p)** | 采样策略 | 从输出概率挑下一个词的方法：Greedy 永远选最大；Temperature 调随机度；Top-k / Top-p 截断长尾低概率词。 |
| **RoPE** | 旋转位置编码 | 现代主流位置表示：按词的位置对 `q, k` 向量做二维角度旋转，0 参数且点积天然只依赖相对距离。 |
| **SwiGLU** | 门控线性单元变体 | 现代 FFN 标配：用 3 个矩阵（`W_gate` 做 SiLU 开关门控 × `W_up` 候选特征 → `W_down` 输出），同参数下效果更强。 |
| **GQA / MQA** | 分组查询注意力 / 多查询注意力 | GQA 让多个 Q 头共用 1 组 K/V（MQA 是全部 Q 共用 1 组），推理时直接成倍压低 KV Cache 显存与带宽。 |
| **MoE** | 混合专家模型 | 把每层巨大的 FFN 拆成多个小“专家网络”，每个词通过路由器只激活其中少数几个，兼顾超大总参数与低推理算力。 |
| **Quantization** | 模型量化 | 用更低精度（如 FP16 → INT8 / INT4）近似存储和计算权重，显著降低显存占用（如 4-bit 约减至 1/4 体积）。 |

## 二、LLM 端到端工作全景（5 步闭环）

无论千亿旗舰模型还是几千万参数的迷你模型，底层的核心任务始终是同一件事：**文本接龙——根据前面已经出现的词，预测下一个最可能出现的词**。

输入一句话（例如 `"今天天气真"`）到吐出下一个词 `"好"`，全流程固定为 5 步：

```text
输入文本："今天天气真"
   │
   ▼  第 1 步：Tokenizer（分词器）     ── 把文字切成块，查表转成整数编号
[102, 58, 903]
   │
   ▼  第 2 步：Embedding（词向量查表）  ── 每个编号查出 1 串固定长度的小数向量
[向量_今天, 向量_天气, 向量_真]     (shape: T × d)
   │
   ▼  第 3 步：Transformer Block × L 层 ── 模型核心大脑（反复加工 L 遍）
       ├─ 上半场 Attention：词与词互相“横向交流”，融合上下文语义
       └─ 下半场 FFN / MLP：每个词关起门来“纵向消化”，提取特征与知识
   │
   ▼  第 4 步：LM Head + Softmax       ── 最后一个词的向量映射回词表打分并归一化成概率
{"好": 72%, "热": 15%, "冷": 8%, ...}
   │
   ▼  第 5 步：Sampling + 自回归循环    ── 挑出 "好" 拼成 "今天天气真好"，回流继续猜下一个
```

## 三、核心大脑：Attention（注意力机制）与多头拆分

### 3.1 为什么需要 Attention？（上下文消歧）

看两句话中的同一个词 `"苹果"`：
- 句子 A：`拍照 用 苹果`
- 句子 B：`咬 一口 苹果`

在第 2 步查词向量表时，两句话里的 `"苹果"` 拿到的是**完全相同的初始向量**（科技属性与水果属性各占一半，例如 `[0.5, 0.5]`）。模型之所以能立刻分清 A 里指手机、B 里指水果，全靠 Attention **动态把前面相关词的信息融进当前词**。

### 3.2 Q、K、V 从哪里来？

在每一层 Attention 中都固定保存着 3 个可学习的权重矩阵 **`W_q`、`W_k`、`W_v`**（句中所有词共用这 3 个矩阵）。把词向量 `x` 分别乘以这 3 个矩阵，就像戴上 3 副不同功能的眼镜，提取出 3 种角色：

- `Q = W_q(X)`（**Query**）：我在找什么线索？
- `K = W_k(X)`（**Key**）：我有什么标签供别人检索？
- `V = W_v(X)`（**Value**）：别人选中我时，我能传递什么实际信息？

> **为什么不直接拿 `x` 自己算相关性，非要拆成 Q/K/V？**
> 直接拿 `x · x` 只会让长相相似的同义词分高（`"苹果"` 最像 `"苹果"` 自己）；但语言里需要强关联的往往属于不同语义类别（如 `"拍照"` 和 `"苹果"`、`"因为"` 和 `"所以"`）。拆出独立的 `W_q` 与 `W_k` 后，模型就能自由地把 `"苹果"` 的 `q` 和 `"拍照"` 的 `k` 对齐到同一方向，再用独立的 `W_v` 专门控制要搬运什么信息。

### 3.3 谁和谁算？（只有当前词的 `q` 会和历史词的 `k, v` 算）

句子里每个词都会生成自己的 `(q, k, v)`，但在计算当前第 3 个词 `"苹果"` 的输出时，**只用到它自己的 `q₃`**，去和 **“之前所有词 + 自己” 的 `k` 和 `v`** 配对计算——前面词的 `q₁, q₂` 仅用于它们各自位置的计算，`"苹果"` 用不到：

```text
               第1词"拍照"        第2词"用"         当前第3词"苹果"
              ┌───────────┐    ┌───────────┐    ┌───────────┐
              │ q₁ (不用)  │    │ q₂ (不用)  │    │    q₃     │ ◀─ 只用当前词自己的 q₃
              │    k₁     │    │    k₂     │    │    k₃     │
              │    v₁     │    │    v₂     │    │    v₃     │
              └─────┬─────┘    └─────┬─────┘    └─────┬─────┘
                    │                │                │
 ① 算相关性：q₃ 点积   k₁               k₂               k₃
                    ▼                ▼                ▼
                 权重 0.68        权重 0.08        权重 0.24
                    │                │                │
 ② 融合内容：加权求和   v₁               v₂               v₃
                    └────────────────┼────────────────┘
                                     ▼
                         "苹果" 的新向量 out₃ = [0.80, 0.12]  (科技维度大幅升高)
```

训练时把所有词拼成矩阵 `Q, K, V`，用以下 7 行核心代码一次并行算出整句话：

```python
d = Q.shape[-1]
scores = (Q @ K.T) / math.sqrt(d)
if causal:
    mask = torch.triu(torch.ones_like(scores, dtype=torch.bool), diagonal=1)
    scores = scores.masked_fill(mask, float("-inf"))
weights = torch.softmax(scores, dim=-1)
output = weights @ V
```

关键细节：
1. **为什么要除以 `√d`**：向量维度 `d` 越大，两向量点积的方差也按比例变大；如果不除以 `√d`，分数绝对值会很大，导致 Softmax 输出极端偏向 `0` 或 `1`、梯度趋近于零学不动。
2. **Causal Mask（因果遮罩）**：用上三角掩码把矩阵右上角（代表“后面的未来词”）填成 `-∞`，经过 Softmax 后严格变成 `0`，杜绝模型在做接龙预测时偷看答案。

### 3.4 Multi-Head Attention（多头注意力）：先投影、再拆分、再汇总

**先纠正一个常见误区：多头注意力会把原始词向量 `x` 先整体乘上 `W_q / W_k / W_v` 投影，再把投影结果拆成多份小向量——它不会直接把原始 `x` 硬砍成几段。**

用“**一份 4 项简历给 2 位面试官各写 2 项摘要**”的例子手算一遍：
- 设原始词向量 `x = [2, 1, 3, 4]`（共 4 维完整信息），设 2 个头（`head_dim = 2`）。
- 整体乘 `4×4` 矩阵 `W_q`：
  - 左 2 列相当于 Head 0 专属的 `4×2` 投影矩阵；右 2 列相当于 Head 1 专属的 `4×2` 投影矩阵。
  - 若 `W_q` 为 `[[1,0,1,1], [2,2,0,1], [0,1,2,1], [1,1,1,2]]`，乘完得 `Q = [8, 9, 12, 14]`：
    - **Head 0 拿到 `[8, 9]`**（`q₀ = 2×1+1×2+3×0+4×1 = 8`，`q₁ = 2×0+1×2+3×1+4×1 = 9`）
    - **Head 1 拿到 `[12, 14]`**（`q₂ = 2×1+1×0+3×2+4×1 = 12`，`q₃ = 2×1+1×1+3×1+4×2 = 14`）
- **结论两句话**：
  1. **看输入时，看的是完整的 4 维**：每个头在提炼这 2 个数时，都已经把完整的 `[2, 1, 3, 4]` 全读了一遍，视野并不残缺；
  2. **干活时，手里只有拆短的 2 维**：各头各自用 2 维去算完自己的注意力后，把输出按顺序拼回 4 维（Concat），再乘一次 `W_o` 汇总融合各头结论。

**为什么要拆成多头，而不保留全维度或只用单头？**
- **为什么开多头**：1 个头无论维度多宽，最终只能算出 **1 组**注意力百分比，遇到复杂句子时指代、动作、修饰线索会挤在一张权重表里摊薄成糊糊；拆成多头就有多张互不干扰的权重表（例如 Head 0 专盯主语，Head 1 专盯动词，Head 2 专盯宾语）。
- **为什么拆短维度**：4 个 `d/4` 维头的总参数量与总算力**与 1 个 `d` 维单头基本相等**；若每头都保留完整 `d` 维，32 个头就会让显存和计算量暴涨 32 倍。

## 四、一块完整的 Transformer Block（“层”的内部构造）

大语言模型所谓“32 层 / 80 层”，指的就是把下面这整块 **Pre-Norm Transformer Block** 积木纵向堆叠 `L` 次（每层结构相同，但拥有各自独立的权重矩阵，不共用）：

```text
输入 x ──┬───────────────────────────────────────▶ (+) ──┬───────────────────────────────▶ (+) ──▶ 输出到下一层
         │                                          ▲    │                                  ▲
         ▼                                          │    ▼                                  │
     [RMSNorm 1] ──▶ [Multi-Head Attention] ────────┘  [RMSNorm 2] ──▶ [FFN 独立思考层] ────┘
                     (上半场：词间横向交流)                             (下半场：逐词纵向深加工)
```

对应的现代标准 Pre-Norm PyTorch 写法：

```python
attn_out, weights = self.attn(self.norm1(x))
x = x + attn_out                  # 上半场结束：残差相加
x = x + self.ffn(self.norm2(x))   # 下半场结束：残差相加
```

各零件不可替代的分工：
1. **位置编码（Positional Encoding）**：Attention 本身不认位置顺序。若去掉位置编码，`"狗咬人很常见"` 与 `"人咬狗很稀奇"` 在最后一个词 `"很"` 看来词集合完全一样，模型彻底分不清主宾语，只能对半瞎猜。
2. **RMSNorm（稳压器）**：计算向量均方根 `rms = sqrt(mean(x²) + eps)` 并按 `(x / rms) * weight` 缩放。它只把数值幅度拉回 `1.0` 左右而不破坏各维相对比例，防止几十层连乘后数值爆炸（NaN）或缩成零。
3. **残差连接（Residual Highway）**：做加法更新 `x + Δx` 而非覆盖，使原始词义和位置信息沿左侧直通到底，也让反向传播梯度畅通无阻。
4. **FFN / MLP（前馈网络，独立思考层）**：**FFN 与 Attention 在同一层内属于平级关系，紧跟 Attention 后作为“下半场”执行。** 只有 Attention 做词间交流；到了 FFN，每个词关起门来独立经过线性升维 → 非线性激活 → 降维输出，不与其他词交流。它承担了全模型约 2/3 的参数，是模型“记忆世界知识与做非线性深加工”的主力仓库。

## 五、现代大模型 3 大主流升级（Llama 3 / Qwen / DeepSeek 标配）

现代开源大模型在基础 Transformer Block 之上，普遍把 3 个部件升级成了更高效的新版本：

### 5.1 RoPE（旋转位置编码）：0 参数表示相对位置

早期的绝对位置嵌入表（`pos_emb`）需要占参数，且外推超过预设长度（如 2048）就会失效。

**RoPE 的做法**：把向量里的特征两两配对当成二维平面上的“时钟指针”，第 `m` 个词就把它的 `q` 和 `k` 指针顺时针旋转 `mθ` 角度（只转 `q, k`，不转 `v`）：
- 第 `m` 个词的 `q_m` 转了 `mθ`，第 `n` 个词的 `k_n` 转了 `nθ`；
- 算点积 `q_m · k_n`（衡量两指针夹角）时，绝对角度相互抵消，**夹角差只取决于 `(m - n)θ` —— 刚好等于两词之间的相对距离**！
- 全程只需按固定三角函数 $\cos(m\theta), \sin(m\theta)$ 做旋转，**占 0 个可训练参数**；并且高维里各对维度像时钟的秒针、分针、时针一样以不同频率旋转，同时精准分辨近邻词距与长距离跨度。

### 5.2 SwiGLU：从 2 个矩阵升级到 3 个矩阵的门控 FFN

经典 FFN 只有一条单行道（`W_up → GELU → W_down`）。**SwiGLU 加了一个“智能水龙头阀门（门控）”**，拆成两路并行相乘再压回：

```python
out = W_down(F.silu(W_gate(x)) * W_up(x))
```

- `W_gate(x)` 经 `SiLU` 激活算出每个特征通道的阀门开度；
- `W_up(x)` 提供候选内容，两者逐元素相乘实现动态筛选；
- `W_down` 压回 `d_model`。
- 为保持总参数与经典 `4d` 相当，中间维度通常从 `4d` 收窄到约 `8/3 d`（`3 × 8/3 d² = 8d²`）。同等参数预算下表达力稳定胜过传统 FFN。

### 5.3 GQA（分组查询注意力）：把 K/V 压缩成 1/4 的推理神器

推理生成时要把历史词的 `K, V` 存进 KV Cache 反复读取。长文本场景下，KV Cache 极易撑爆显存并拖慢内存带宽。

研究发现 Q 需要足够多头才能维持多视角，但 K/V 信息高度冗余。于是 **GQA 让多个 Q 头“拼团”共用同一份 K 和 V**（如 Llama-3 8B 采用 32 个 Q 头配 8 个 KV 头，即 **4:1 分组**）：
- `W_q` 仍输出 32 个头（4096 维），但 `W_k` 和 `W_v` 只需输出 8 个头（1024 维），参数量降为 **1/4**；
- 推理阶段需要缓存与读取的 **KV Cache 体积和显存带宽也直接降为 1/4**，大幅提速且几乎不损模型精度。
- （极端情况所有 Q 头共用 1 组 KV 叫 **MQA**；一对一不共享叫传统 **MHA**。）

## 六、训练与推理的底层机制

### 6.1 训练规则：梯度下降与反向传播

训练开始时，所有矩阵里的数字全是随机数。训练就是不断重复 **“前向猜词 → 算交叉熵 Loss → 反向传播算梯度 → 优化器改数字”**：

```python
logits = model(x)                  # 1. 前向猜测每个位置下一个词的打分
loss = F.cross_entropy(logits, y)  # 2. 对比真实下一个词 y，算出猜错程度
optimizer.zero_grad()              # 3. 清空上一轮梯度缓存
loss.backward()                    # 4. 反向传播：链式法则倒推算出每个参数的 grad
optimizer.step()                   # 5. 优化器按梯度更新所有矩阵里的数字
```

改数字的最底层规则是**梯度下降**：

$$\text{新参数} = \text{旧参数} - \text{学习率} \times \text{梯度}$$

- **极简手算例**：设模型只有 1 个参数 `w`（初始随机 `w = 3`），规则 `预测 = w × x`。题目输入 `x = 2`，正确答案 `10`，误差 `Loss = (2w - 10)²`。
  - 前向：预测 `6`，`Loss = (6 - 10)² = 16`。
  - 求梯度：对 `w` 求导得 `梯度 = 2 × (6 - 10) × 2 = -16`（负号表示调大 `w` 能让 Loss 变小）。
  - 更新（设学习率 `0.05`）：`新 w = 3 - 0.05 × (-16) = 3.8` → 新预测 `7.6`，新 Loss 降至 `5.76`。几轮后稳定收敛在 `w = 5.0`（预测 `10`，梯度归 `0`）。
- **为什么叫反向传播**：中间隔了十几层时，靠微积分**链式法则**从 Loss 倒着逐层把“误差责任”往回传（每层只需把后层传回的梯度乘上自己这一步的局部导数），一次倒推就能算出全模型所有参数的梯度。
- **为什么常用 `AdamW`**：在基础减法上加入了**动量惯性**（下坡平滑加速）、**自适应步长**（各参数按历史梯度波动自动调步幅）和**权重衰减**（防权重过大过拟合）。

### 6.2 推理机制：锁死权重 + 关掉反向传播 + KV Cache

训练结束后保存权重文件（`.safetensors` / `.pt` / `GGUF`）。**推理（Inference）的核心在于锁死所有权重数字、彻底关闭反向传播（`@torch.no_grad()` + `model.eval()`），只执行前向计算。**

| 对比维度 | 训练（Training） | 推理（Inference） |
|---|---|---|
| **权重状态** | 每步用 `loss.backward()` + `optimizer.step()` 改写参数 | **只读锁死**，不记录梯度计算图 |
| **执行方式** | 持有完整语料，一次并行算出全句每个位置的预测 | **Prefill** 并行读入提示词 → **Decode** 逐词自回归接龙 |
| **输出处理** | 用概率分布算 Cross-Entropy Loss，不挑词 | 用采样策略（Greedy / Temperature / Top-k / Top-p）挑选下一个词 |
| **显存需求** | 需存权重 + 梯度 + 优化器状态 + 激活值（常达权重体积 4～6 倍+） | 只需存权重 + **KV Cache**（还可量化压低体积） |

> **为什么推理时只缓存 KV，不缓存 Q？**
> 因为在生成第 `t` 个新词时，历史词的 `q` 已经用完丢弃了；只有历史词算好的 `k` 和 `v` 固定不变且需要被后续每一个新词的 `q_t` 反复查询，缓存下来即可避免重复计算整段前文。

## 七、真实大模型的层级定义、参数组成与显存速算

真实大模型的结构与迷你教学版完全同源：外部固定为 **入口 `Embedding` + 主干 `L` 层 Transformer Block + 出口 `Final RMSNorm & LM Head`** 三段式。

### 7.1 实例精算：Llama-3 8B（8,030,261,248 参数）

核心超参数：词表 `V = 128,256`，向量宽度 `d = 4,096`，层数 `L = 32`（32 Q 头 / 8 KV 头，GQA 4:1），FFN 中间维度 `14,336`，位置编码采用 0 参数 RoPE。

| 组成部分 | 包含权重矩阵 | 尺寸与计算明细 | 参数量 | 占比 |
|---|---|---|---|---|
| **① 入口 `tok_emb`** | 词向量查找表 | `128,256 × 4,096` | **5.25 亿** (`525,336,576`) | 6.5% |
| **② 32 层 Attention** | 每层 `W_q, W_k, W_v, W_o` | `W_q, W_o`: 各 `4096×4096`<br>`W_k, W_v`: 各 `4096×1024`<br>单层 `41,943,040 × 32` | **13.42 亿** (`1,342,177,280`) | 16.7% |
| **③ 32 层 SwiGLU FFN** | 每层 `gate / up / down` | `3 × (4096 × 14,336)`<br>单层 `176,160,768 × 32` | **56.37 亿** (`5,637,144,576`) | **70.2%** |
| **④ 65 个 RMSNorm** | 每层 2 个 + 尾部 1 个 | `65 × 4,096` | **26.6 万** (`266,240`) | 0.003% |
| **⑤ 出口 `lm_head`** | 输出打分矩阵 | `4,096 × 128,256` | **5.25 亿** (`525,336,576`) | 6.5% |
| **全模型总计** | — | 精确合计 | **80.30 亿 (`8,030,261,248`)** | **100%** |

> 关键规律：**FFN 占掉约 70% 的全模型参数**；**RMSNorm 仅占 0.003%** 却决定深层训练能否稳定；RoPE 本身不占参数。

### 7.2 不同量级规模与显存速算

| 规模定位 | 代表模型 | 层数 `L` | 向量宽度 `d` | 纯权重推理显存（BF16，2 字节/参数） |
|---|---|---|---|---|
| **迷你实验级（~30M）** | 入门从零预训练 | 6～8 层 | 384～512 | ~60 MB（单卡 T4 几分钟可训） |
| **端侧轻量级（1.5B–3B）** | Qwen2.5-1.5B / Llama-3.2-3B | 28 层 | 1,536～3,072 | ~3–6 GB |
| **主流甜点级（7B–8B）** | Qwen2.5-7B / Llama-3-8B | 28～32 层 | 3,584～4,096 | ~15–16 GB |
| **大型稠密级（70B）** | Llama-3-70B | 80 层 | 8,192 | ~140 GB |
| **超大稀疏级（MoE）** | DeepSeek-V3（671B 总参） | 61 层 | 7,168 | 每层仅路由激活少数专家，推理算力远低于同总参稠密模型 |

**显存速算口诀**：
- **BF16 / FP16 半精度推理**：每个参数占 2 字节 → **每 1B（10 亿）参数 ≈ 2 GB 显存**（再额外预留上下文 KV Cache 空间）。
- **INT4 量化推理**：每个参数占 0.5 字节 → **每 1B 参数 ≈ 0.5 GB 显存**（外加少许量化缩放系数开销）。
