# Embedding 层与模型规模原理参考手册

本文承接 [Byte-level BPE 参考手册](./byte-level-bpe.md)，系统梳理大语言模型（LLM）在拿到离散 Token ID 之后的第一道神经网络层——**Embedding（词向量查表）**，以及围绕它的联合训练、位置编码演进、权重共享与模型参数量计算方法。

---

## 一、Embedding 在 LLM 全链路中的位置

Tokenizer（Byte-level BPE）输出的是整数序列（例如 `[283, 262]`）。这些整数只是词表里的“学号”——编号大小本身不代表语义远近，也无法做反向传播求导。**Embedding 层负责把离散整数 ID 映射成连续、可微的浮点数向量**，作为后续几十层 Transformer 的真正输入：

```text
原始文字 ("hello 你好")
   │
   ▼  ① Tokenizer (Byte-level BPE)  ── 纯统计规则、不可训练、阶段 1 提前锁死
Token ID 序列: [283, 262]           ── shape: [batch, T]（离散整数）
   │
   ▼  ② Embedding（词向量查表）       ── 可训练矩阵 W_emb [V, d]（阶段 2 神经网络起点）
向量序列: [[0.12, -0.8, ...], ...]  ── shape: [batch, T, d]（连续可微浮点数）
   │
   ▼  ③ Transformer Block × L 层（Attention + FFN）
   │
   ▼  ④ LM Head + Softmax + Sampling
```

---

## 二、查表本质与稀疏梯度更新

### 2.1 数学等价：`nn.Embedding` = `One-hot @ W_emb`（无偏置线性层）

设词表大小 $V = 4$（`{0: "猫", 1: "狗", 2: "汽车", 3: "火箭"}`），向量维度 $d = 3$。Embedding 层是一张形状为 `[4, 3]` 的可学习浮点数表格 $W_{\text{emb}}$：

```text
行 0 ("猫")  : [ 0.90,  0.80, -0.10]
行 1 ("狗")  : [ 0.85,  0.75,  0.00]
行 2 ("汽车"): [-0.70,  0.20,  0.90]
行 3 ("火箭"): [-0.80,  0.10,  0.95]
```

- **数学视角**：把 Token ID `1`（`"狗"`）写成 One-hot 向量 `[0, 1, 0, 0]` 乘以矩阵 $W_{\text{emb}}$，结果恰好取出第 `1` 行 `[0.85, 0.75, 0.00]`。因此 Embedding 在数学上等价于一个**无偏置（`bias=False`）的线性投影层**。
- **工程视角**：真实模型词表常达十几万（如 Llama 3 的 `V = 128,256`），One-hot 矩阵绝大多数元素为 `0`。`nn.Embedding` 直接拿整数 ID 作为行下标索引 `W_emb[ids]`：
  - **前向复杂度**：从 $O(V \cdot d)$ 降至 $O(d)$；
  - **稀疏梯度更新**：反向传播时只把梯度累加到本轮句子里**实际出现过的行**，未出现过的词行梯度严格保持 `0.0`。

## 三、随机初始化如何自动学出语义（静态 vs 动态边界）

训练开始时，矩阵 $W_{\text{emb}}$ 全部由随机高斯噪声填充。它之所以能自动长出语义结构，完全来自 **Next-Token Prediction（预测下一个词）** 的反向传播推力：

1. 训练语料中，相似词往往出现在高度重合的上下文里（例如 `"我养猫很可爱"` / `"我养狗很可爱"`，`"小猫爱玩球"` / `"小狗爱玩球"`）。
2. 为把 `"猫"` 后面接 `"很"` / `"爱"` 的概率调高，反向传播沿输出误差计算梯度，把 `"猫"` 的向量推向能激活这些后续词的方向；
3. 遇到 `"狗"` 时，同样的后续目标把 `"狗"` 的向量推向几乎一致的方向；
4. 经过海量语料迭代后，语义相近的词在高维空间里自然聚拢，而 `"猫"` 与 `"汽车"` 等不同类别则保持明显距离。

> **关键边界：Embedding 输出的是静态词向量**
> 无论句子是 `"吃一口苹果"` 还是 `"用苹果拍照"`，`"苹果"` 在 Embedding 层查出来的永远是**完全同一行向量**（同时混杂水果与手机两类特征）。根据上下文消歧并把向量推向正确含义，由紧随其后的 **Attention 层**完成。

## 四、位置编码的两代演进

Embedding 只把每个 Token 独立映射为向量，不包含出现顺序。若缺乏位置信号，`"狗咬人"` 与 `"人咬狗"` 在无序集合下无法区分。现代架构经历了两代位置注入方式：

| 时代 | 代表模型 | 做法 | 特点与取舍 |
|---|---|---|---|
| **第一代：绝对位置相加** | GPT-2、BERT | 额外维护一张 `[max_len, d]` 的位置表 `pos_emb`，在 Embedding 后直接逐元素相加：`x = tok_emb(ids) + pos_emb(pos)` | 实现简单，但消耗额外参数；推理长度超出训练时的 `max_len` 就失去对应行，长上下文外推能力弱 |
| **第二代：RoPE（旋转位置编码）** | Llama 3、Qwen、DeepSeek | **Embedding 层不加任何位置信息**；推迟到每层 Attention 中，把 `Q` 和 `K` 的特征两两配对做二维角度旋转 `mθ` | **0 可训练参数**；点积 `q_m · k_n` 天然只依赖相对距离 `(m - n)`；长上下文外推能力远强于绝对位置表 |

## 五、Weight Tying（权重共享）

对比模型入口和出口的两张词表矩阵：
- **入口 `tok_emb`**（`[V, d]`）：输入 Token ID → 查出 `d` 维词向量；
- **出口 `lm_head`**（`[d, V]`，转置后同为 `[V, d]`）：把最终隐藏向量与词表里全部 $V$ 个词向量做点积算相似度（Logits），得分最高者最可能是下一个词。

两者执行的是互逆映射，因此许多模型让头尾共用同一份底层存储（`lm_head.weight = tok_emb.weight`）：
- **中小模型常用**（GPT-2、Gemma、Qwen2.5-0.5B/1.5B/3B）：小模型中单张词表即可占掉 20%～50% 总参数，共享一份能直接省去 $V \cdot d$ 个参数，并强制出入口共用同一套语义坐标系。
- **大型模型常拆开**（Llama-3 8B/70B、Qwen2.5-72B）：模型主体变大后词表占比降至个位数百分比（如 Llama-3 8B 单份词表占 6.5%），头尾独立参数能提供更高表达自由度。

## 六、核心辨析与延伸问答

### 6.1 LLM 自带 Token Embedding 层 vs RAG 独立 Embedding 模型

| 对比维度 | LLM 自带的 **Token Embedding 层** | RAG 用的 **独立 Embedding 模型**（如 BGE / text-embedding-3） |
|---|---|---|
| **本质** | LLM 内部第 1 层查找表（`nn.Embedding`） | 完整的独立神经网络（自带查表层 + 多层 Transformer） |
| **输入 → 输出** | **1 个 Token** → 1 个静态词向量 | **一整段文本** → 1 个融合上下文的句向量 |
| **上下文感知** | 无（静态查表，同词永远输出同一行） | 有（经多层 Attention 消歧，能区分 `"吃苹果"` 与 `"买苹果"`） |
| **工程用途** | 给 LLM 主干提供连续向量输入，与本模型词表强绑定 | 用于向量数据库存储与语义相似度检索（RAG 召回） |

### 6.2 为什么 Embedding 能与 Transformer 联合训练，而 BPE 必须单独提前训练？

1. **可微计算图边界**：BPE 输出的是离散整数下标，无法对“选 ID 10 还是 ID 11”求导，梯度在 Tokenizer 出口截断；Embedding 输出连续浮点数向量（等价于 `One-hot @ W_emb`），使交叉熵 `Loss` 的梯度能一路反向传播回 `W_emb`。
2. **端到端联合优化**：`Embedding`（发报员）与 `Transformer`（解报员）共用同一个预测误差 `Loss`。多元梯度沿同一合力方向同步微调两者，使 Embedding 自发学出最容易被后续 Transformer 消化的表示。
3. **两阶段强绑定约束**：阶段 1 用纯 CPU 统计训练好 BPE 后，词表 ID 与 Embedding 行号即形成强绑定，进入阶段 2（GPU 联合训练）及后续推理时 BPE 规则必须保持只读锁死。

### 6.3 模型大小（参数量）是如何确定的？

模型参数量在开训前由 5 个架构超参数直接决定：**词表大小 `V`**、**向量宽度 `d`**（呈 $d^2$ 放大）、**层数 `L`**、**FFN 中间宽度 `d_ff`**（SwiGLU 下约 $2.7d \sim 3.5d$，占全模型约 70% 参数）以及 **GQA 头配置 `n_heads / n_kv_heads`**。

通用估算公式（现代稠密 LLM，头尾不共享权重时）：

$$N \approx 2Vd + L \times (11 \sim 13)\, d^2$$

例如 Llama-3 8B（`V=128,256, d=4,096, L=32, d_ff=14,336`, GQA 4:1）总计精确为 `8,030,261,248`（`8.03B`）参数。工程档位（如 1.5B / 3B / 8B / 32B / 70B）主要由三项现实约束决定：
1. **推理显存卡位**：BF16 下 **1B 参数 ≈ 2 GB 显存**（INT4 量化 ≈ 0.5 GB/B），还需预留 KV Cache 空间——8B 卡在单张 24GB 消费卡（如 4090），32B 卡在单张 80GB 数据中心卡，70B 对应双卡 80GB。
2. **Scaling Laws 与 Over-training**：计算量近似 $C \approx 6ND$。现代主力小/中模型常喂入远超 Chinchilla `1:20` 比例的语料（例如 Llama 3 8B 训练 15T Token），用一次性训练算力换取极低的线上推理成本。
3. **深宽比与硬件维度匹配**：`d / L` 经验上常保持在 `80 ~ 130` 之间，且 `d`、`d_ff`、`V` 取 `64 / 128 / 256` 的整数倍以跑满 GPU Tensor Core 吞吐。

### 7.1 PyTorch 本地实测结果（`02-embedding/embedding_demo.py`，运行设备：`mps`）

1. **查表等价性**：`V=6, d=4`，`nn.Embedding` 输出与 `F.one_hot(...) @ emb.weight` 的最大绝对误差 `max_abs_diff = 0.00e+00`。
2. **稀疏梯度与联合反向传播**：仅输入 `ids = [0, 2]`（`loss = 2.1225`），`emb.weight.grad` 中第 `0` 行（`0.375295`）、第 `2` 行（`0.254739`）与上游 `proj.weight.grad`（`1.872977`）同步获得梯度，未出现的行 `[1, 3, 4, 5]` 梯度 L2 范数严格为 `0.000000`。
3. **语义自动聚拢（`V=20, d=4`，32 组相邻 `(x_t, x_{t+1})` 样本，500 步 AdamW）**：训练 Loss 从 `3.3938` 降至 `0.3507`（接近理论信息熵下界 `0.5 × ln(2) ≈ 0.3466`），随机初始化词向量的余弦相似度变化如下：

| 词对 | 关系类别 | 训练前余弦相似度 | 训练后余弦相似度 |
|---|---|---:|---:|
| `("猫", "狗")` | 同语境宠物名词 | `-0.3744` | **`+0.9908`** |
| `("汽车", "火箭")` | 同语境载具名词 | `-0.3429` | **`+0.9996`** |
| `("猫", "汽车")` | 跨类别无关词 | `-0.2036` | `+0.2715` |
| `("狗", "火箭")` | 跨类别无关词 | `+0.1443` | `+0.1653` |

4. **Weight Tying 验证（`V=1000, d=128`）**：不共享权重共 `256,000` 参数；共享后底层 `data_ptr()` 指针一致，总参数降至 `128,000`，精确省去 `V × d = 128,000` 个参数。
